# HA Smart Dehumidifier

🇬🇧 [English](README.md)

Home Assistant інтеграція, яка перетворює звичайний розумний вимикач на
повноцінний пристрій "розумний осушувач" + відповідна картка для
Lovelace.

Уся логіка — вмикання/вимикання вентилятора, авто-режим, ручний режим,
таймери — працює **всередині самої інтеграції**. Жодних
`input_boolean`, `input_number`, `timer`-helper'ів чи окремих
автоматизацій створювати не потрібно — усе нижче вже вбудовано.

![Картка — активний авто-режим](docs/images/card-auto-mode.jpg)

## Можливості

- Обгортає будь-яку сутність `switch` (розумну розетку, реле — що
  завгодно) у пристрій `humidifier` з керуванням цільовою вологістю.
- **Авто-режим**: розраховує рекомендовану цільову вологість за
  вологістю сусідньої ("референтної") кімнати (за бажанням — з
  корекцією на різницю температур між кімнатами), і керує
  вентилятором з гістерезисом, щоб реле не "деренчало".
- **Ручний режим**: перемикач в один дотик, що вмикає вентилятор на
  налаштовану тривалість, а потім ставить авто-режим на паузу, щоб
  той одразу ж не перебив ваше ручне втручання.
- Працює й **зовсім без додаткових датчиків** — див.
  [Використання без датчиків автовологості](#використання-без-датчиків-автовологості)
  нижче.
- Кастомна картка Lovelace з круговим повзунком, живим статусом і
  розширеним візуальним редактором (розкладка, кольори, шрифти,
  анімації) — жодного YAML не потрібно.

## Встановлення через HACS

1. HACS → Custom repositories → додати цей репозиторій (тип:
   **Integration**).
2. Встановити "HA Smart Dehumidifier", потім **перезапустити** Home
   Assistant (reload після першого встановлення недостатньо).
3. Settings → Devices & services → Add integration → **HA Smart
   Dehumidifier**.

## Налаштування пристрою

При додаванні інтеграції буде запропоновано:

| Поле | Обов'язково? | Для чого |
|---|---|---|
| **Вимикач вентилятора** | Так | Реальна сутність `switch`, яка фізично вмикає/вимикає вентилятор. Без неї пристрій нічим не керує. |
| **Датчик вологості (кімната з осушувачем)** | Ні | Поточна вологість у кімнаті з осушувачем. Потрібен для авто-режиму й для показу поточної вологості. |
| **Датчик температури (кімната з осушувачем)** | Ні | Використовується разом з двома полями нижче для розрахунків з корекцією на температуру. |
| **Датчик вологості (сусідня кімната), %** | Ні | Вологість референтної/сусідньої кімнати — використовується для розрахунку рекомендованої цілі. |
| **Датчик температури (сусідня кімната)** | Ні | Див. [Навіщо два датчики температури](#навіщо-два-датчики-температури) нижче. |

**Обов'язковий лише вимикач вентилятора.** Лишіть будь-яке поле
датчика порожнім, якщо його немає — пристрій все одно запрацює,
просто в простішому режимі (див. два режими використання нижче). Будь-
яке з цих полів можна додати чи змінити пізніше без пересворення
пристрою: **Settings → Devices & services → HA Smart Dehumidifier →
⋯ → Reconfigure**.

Після створення пристрою інтеграція додає такі сутності:

| Сутність | Тип | Призначення |
|---|---|---|
| `humidifier.<name>` | `humidifier` | Головна сутність — увімк/вимк, цільова вологість, поточна вологість. Саме на неї вказує картка. |
| `sensor.<name>_status` | `sensor` | Поточний статус: `off` / `connecting` / `auto` / `idle` / `manual` / `manual_auto` / `pause` — див. таблицю нижче. |
| `sensor.<name>_recommended_humidity` | `sensor` | Авто-розрахована рекомендована ціль (має сенс лише з налаштованими датчиками вологості). |
| `sensor.<name>_absolute_humidity_room` | `sensor` | Абсолютна вологість (г/м³) кімнати з осушувачем. |
| `sensor.<name>_absolute_humidity_neighbor` | `sensor` | Абсолютна вологість (г/м³) сусідньої кімнати. |
| `switch.<name>_auto_mode` | `switch` | Вмикає/вимикає авто-режим. |
| `button.<name>_manual_toggle` | `button` | Та сама дія, що й кнопка "MANUAL" на картці. |
| `number.<name>_delta` | `number` | Див. [Довідник налаштувань](#довідник-налаштувань). |
| `number.<name>_min_humidity` | `number` | ″ |
| `number.<name>_max_humidity` | `number` | ″ |
| `number.<name>_manual_runtime` | `number` | ″ |
| `number.<name>_manual_pause` | `number` | ″ |

### Навіщо два датчики температури

Однакова *відносна* вологість при різній температурі відповідає різній
кількості води в повітрі, тож пряме порівняння відсотків між кімнатами
некоректне. Якщо вказано **обидва** датчики температури, інтеграція:

1. рахує абсолютну вологість (г/м³) сусідньої кімнати за її вологістю
   й температурою (формула Magnus-Tetens);
2. додає налаштовану дельту — **теж в абсолютних одиницях (г/м³)** у
   цьому режимі — до цього значення;
3. перераховує суму назад у *відсоткову* вологість для температури
   кімнати з осушувачем — це і є рекомендована/цільова вологість, яку
   ви бачите на картці.

Якщо хоча б один датчик температури не вказано, інтеграція автоматично
перемикається на пряме порівняння відсотків: дельта тоді у відсоткових
пунктах, додається прямо до показника вологості сусідньої кімнати.
Перемикання повністю автоматичне — воно також змінює одиницю виміру
`number`-сутності дельти (`%` або `г/м³`) — нічого вручну перемикати
не потрібно, досить лише додати чи прибрати датчик температури.

## Додавання картки

**Спочатку створіть пристрій (див. вище), і лише потім додавайте
картку** — без готового пристрою картці нема що показувати.

Картка реєструється автоматично — ресурс Lovelace вручну додавати не
потрібно (якщо все ж не з'явилась — див.
[Якщо картка не з'являється](#якщо-картка-не-зявляється-custom-element-doesnt-exist)
нижче). У режимі YAML достатньо вказати тип:

```yaml
type: custom:ha-smart-dehumidifier
```

Після цього відкрийте **візуальний редактор** картки і на вкладці
"Сутності" 🔗 оберіть **Пристрій (HA Smart Dehumidifier)**, який ви
створили — його головну сутність `humidifier`. Усе інше (вимикач
вентилятора, датчики, статус, перемикач авто-режиму, number-сутності)
картка знаходить сама — призначати їх вручну не потрібно.

Або одразу в YAML, тим самим кроком:

```yaml
type: custom:ha-smart-dehumidifier
entity: humidifier.smart_xxx
```

Усі візуальні налаштування (розкладка, дуга, кольори, анімації,
7-segment шрифт, нижні кнопки, бейдж тощо) редагуються в тому самому
візуальному редакторі — див.
[Візуальний редактор](#візуальний-редактор) нижче з описом кожної
вкладки.

## Як користуватися

### Використання з датчиками автовологості

Цей режим доступний, коли налаштовано хоча б датчик поточної
вологості (а в ідеалі — ще й датчик сусідньої кімнати та обидва
датчики температури):

1. Увімкніть пристрій (кнопка **OFF** зліва внизу).
2. Лишіть **авто-режим** увімкненим (він увімкнений за замовчуванням —
   бейдж вгорі картки показує "АВТО xx%"). Інтеграція постійно
   перераховує рекомендовану цільову вологість за вашими датчиками й
   синхронізує з нею вентилятор автоматично.
3. За потреби одноразово підлаштуйте розрахунок під свою кімнату через
   `number.<name>_delta` / `_min_humidity` / `_max_humidity` (або
   через шестерню на картці) — див.
   [Довідник налаштувань](#довідник-налаштувань).
4. Все — у щоденному використанні більше нічого чіпати не потрібно.

Якщо ви перетягнете дугу, натиснете +/-, або торкнетесь панелі
цільової вологості — це стане одноразовим ручним перевизначенням
*цільового значення* й одразу вимкне авто-режим (щоб наступне ж
оновлення з датчиків не перезаписало ваш вибір) — увімкніть
`switch.<name>_auto_mode` назад, коли захочете повернути автоматичний
розрахунок.

### Використання без датчиків автовологості

Якщо ви налаштували лише вимикач вентилятора (або немає датчика
сусідньої кімнати), пристрій все одно повністю робочий — просто йому
нема з чого розраховувати ціль, тож ви керуєте нею вручну:

1. Увімкніть пристрій.
2. Задайте цільову вологість самостійно дугою / кнопками +/- /
   панеллю цілі. Ручна зміна цілі завжди вимикає авто-режим, тож це
   тут звичайний спосіб роботи — нічого спершу вимикати не потрібно.
3. Якщо у вас є *лише* датчик поточної вологості кімнати (без датчика
   сусідньої кімнати), вентилятор все одно вмикатиметься/вимикатиметься
   навколо заданої вами цілі, за тією ж логікою гістерезису, що й у
   авто-режимі — просто ціль задаєте ви самі, а не інтеграція.
4. Якщо **жодного** датчика вологості немає, користуйтесь кнопкою
   **MANUAL** (справа внизу): вона запускає вентилятор на фіксовану
   тривалість (`number.<name>_manual_runtime`, 20 хв за замовчуванням),
   а потім ставить паузу (`number.<name>_manual_pause`) перед тим, як
   знову розглядати авто-поведінку — натисніть її знову будь-коли для
   нового запуску, або натисніть під час роботи, щоб зупинити достроково.

## Як працює авто-режим

Вентилятор вмикається й вимикається за асиметричним гістерезисом
навколо цільової вологості (яку в авто-режимі інтеграція рахує сама —
див. [Навіщо два датчики температури](#навіщо-два-датчики-температури)
— а в ручному використанні задаєте ви):

- **Вмикається**, щойно поточна вологість дорівнює цільовій чи
  перевищує її (`поточна >= ціль`) — без затримки, реагує одразу.
- **Вимикається**, лише коли поточна вологість опуститься нижче
  цільової на величину **гістерезису** (`поточна <= ціль − гістерезис`,
  за замовчуванням 5%).

Це працює однаково незалежно від того, чому саме різниця "поточна −
ціль" змінилась: впала вологість чи просто підняли ціль. Наприклад,
при гістерезисі 5% і цілі 65%: вентилятор вмикається, щойно вологість
сягає 65%, і вимикається, коли вона опуститься до 60% — або одразу,
якщо підняти ціль до 65%+, поки вологість лишається на рівні 60% чи
нижче. Такий запас потрібен лише на вимкнення — щоб реле не клацало
щоразу, як вологість на мить торкнеться цілі.

Кілька важливих нюансів поведінки:

- **Ручна зміна цільової вологості** (повзунок, кнопки +/-, клік по
  панелі) одразу вимикає авто-режим — щоб наступна ж синхронізація з
  датчиків не перезаписала вибір користувача.
- Кнопка **"Ручний"** завжди інвертує фактичний стан вентилятора: якщо
  зараз крутиться — ставить на паузу; якщо стоїть — вмикає ручним
  таймером (тривалість налаштовується, за замовчуванням 20 хв).
- Після завершення ручного режиму (сплив таймер або вимкнули вручну)
  починається **пауза** (за замовчуванням 20 хв), протягом якої
  авто-режим тимчасово не керує вентилятором — це навмисно, щоб
  ручне втручання не перебивалось одразу ж автоматикою.
- Фізичний вимикач вентилятора теж враховується: якщо його ввімкнули
  "руками" (не через авто-режим) — це стартує ручний режим; вимкнули
  під час ручного — ставить на паузу.

Сутність статусу (`sensor.<name>_status`) відображає, яка саме з цих
причин зараз керує вентилятором:

| Статус | Значення |
|---|---|
| `off` | Пристрій вимкнено. |
| `connecting` | Увімкнено, але датчик поточної вологості ще недоступний (типово — перші секунди після рестарту HA). |
| `auto` | Вентилятор фактично працює через спрацювання вологості. |
| `idle` | Увімкнено, вентилятор не працює — вологість ще не досягла цілі. |
| `manual` | Ручний режим, вологість ще не спрацювала. |
| `manual_auto` | Ручний режим і вологість вже спрацювала одночасно. |
| `pause` | Ручний режим щойно вимкнено — коротка пауза перед поверненням авто-визначення. |

## Візуальний редактор

Відкрийте налаштування картки (іконка шестерні), щоб отримати
візуальний редактор з вкладками — жодного YAML для цього не потрібно:

| Вкладка | Що охоплює |
|---|---|
| 🔗 **Сутності** | Пристрій (`humidifier`), на який вказує картка. |
| 📐 **Розкладка** | Відступи картки, заокруглення кутів, вирівнювання, пропорції "скла" по ширині/висоті для десктопу/широких екранів. |
| 🔵 **Дуга та повзунок** | Круговий повзунок — кольори доріжки/ручки, товщина, стиль ручки перетягування. |
| 🪄 **Автовологість** | Бейдж "АВТО xx%" вгорі картки, коли авто-режим увімкнено. |
| 💧 **Поточна вологість** | Великий 7-segment індикатор — розміри, жирність, інтервали для цілої, десяткової частин і `%`. |
| 🎯 **Панель цільової вологості** | Панель з числом і кнопками ± під індикатором. |
| 🔘 **Нижні кнопки** | Кнопки OFF / статус вентилятора / MANUAL, їхні підписи та іконки, і бейдж статусу. |
| ✨ **Візуальні ефекти** | Фонова анімація вентилятора, "комета" на орбіті, ефект частинок. |

## Довідник налаштувань

Змінюються двома способами: живо, через шестерню на картці
(зберігається назавжди, переживає перезапуски); або одноразово, як
стартові значення — **Settings → Devices & services → HA Smart
Dehumidifier → Configure**.

| Параметр | Значення за замовчуванням | Діапазон |
|---|---|---|
| Дельта вологості понад сусідню кімнату | 3.75 (`%` або `г/м³`, автоматично) | 0–10 |
| Мінімальна рекомендована вологість | 65% | 0–100 |
| Максимальна рекомендована вологість | 85% | 0–100 |
| Толерантність гістерезису (лише в Configure) | 5% | — |
| Тривалість ручного режиму | 20 хв | 1–180 |
| Пауза після ручного режиму | 20 хв | 1–180 |

Мін./макс. рекомендована вологість обмежують лише
**авто-розраховану** ціль. Ручне встановлення цілі (дуга, кнопки +/-,
панель цілі) завжди приймає повний діапазон 0–100%, незалежно від цих
меж.

## Якщо картка не з'являється ("Custom element doesn't exist")

1. Перевірте, що інтеграція реально завантажилась: **Settings →
   System → Logs** → пошук `ha_smart_dehumidifier`. Помилка реєстрації
   ресурсу там же підкаже, що робити.
2. Відкрийте дашборд у браузері, F12 → Network, онові сторінку і
   перевірте запит `/ha_smart_dehumidifier_files/index.js` — має бути
   **200**, а не 404. 404 означає, що інтеграція не завантажилась
   (перевірте логи) або Home Assistant потрібно повністю
   **перезапустити** (не reload) після встановлення через HACS.
3. Жорстко онови кеш браузера (Ctrl+Shift+R / Cmd+Shift+R).
4. Якщо нічого з вищого не допомогло — додайте ресурс вручну:
   **Settings → Dashboards → ⋮ → Resources → Add resource** → URL
   `/ha_smart_dehumidifier_files/index.js`, тип **JavaScript Module**.
