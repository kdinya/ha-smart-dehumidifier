# HA Smart Dehumidifier

Home Assistant інтеграція для керування осушувачем вологого приміщення
(звичайний вентилятор через розумний вимикач) + картка для Lovelace.

Уся логіка (вмикання/вимикання вентилятора, авто-режим, ручний режим,
таймери) працює всередині самої інтеграції — жодних `input_boolean`,
`input_number`, `timer`-helper'ів чи окремих автоматизацій створювати не
потрібно.

## Швидкий старт

1. Встанови інтеграцію через HACS.
2. Settings → Devices & services → Add integration → **HA Smart
   Dehumidifier** — створи пристрій (детально нижче).
3. Тільки **після** цього додай картку на дашборд і обери щойно
   створений пристрій.

## Встановлення через HACS

1. HACS → Custom repositories → додати цей репозиторій (тип: Integration).
2. Встановити "HA Smart Dehumidifier", перезапустити Home Assistant.
3. Settings → Devices & services → Add integration → **HA Smart
   Dehumidifier**.
4. Вказати:
   - **Вимикач вентилятора** (обов'язково) — реальний `switch`, який
     фізично вмикає вентилятор. Без нього пристрій нічим не керує.
   - **Датчик вологості** у приміщенні з осушувачем (необов'язково).
   - **Датчик вологості** сусіднього (референтного) приміщення
     (необов'язково).
   - **Датчик температури** приміщення з осушувачем (необов'язково) —
     потрібен для коректного перерахунку між кімнатами (див. нижче).
   - **Датчик температури** сусіднього приміщення (необов'язково) —
     так само.

   Обов'язковий лише вимикач вентилятора. Решта полів потрібна тільки
   для авто-розрахунку цільової вологості — якщо якогось датчика немає,
   просто лиши поле порожнім: пристрій запрацює й без нього (в ручному
   режимі або з дефолтними межами вологості, які завжди можна змінити
   пізніше).
5. Після створення пристрою інтеграція автоматично додасть такі
   сутності: `humidifier` (головна сутність), `sensor` — статус,
   рекомендована вологість, абсолютна вологість кімнати й сусідньої
   кімнати (г/м³), `switch` — авто-режим, `button` — ручний режим,
   `number` × 5 — дельта, мін./макс. вологість, тривалість/пауза
   ручного режиму.

### Навіщо два датчики температури

Однакова відносна вологість при різній температурі відповідає різній
кількості води в повітрі, тож пряме порівняння відсотків між кімнатами
некоректне. Якщо вказано обидва датчики температури, інтеграція:

1. рахує абсолютну вологість (г/м³) сусідньої кімнати за її вологістю й
   температурою (формула Magnus-Tetens);
2. додає дельту — **теж в абсолютних одиницях (г/м³)** — до цього значення;
3. перераховує суму назад у відсотки відносної вологості для температури
   кімнати з осушувачем — це і показується як рекомендована/цільова
   вологість (%).

Якщо хоча б один датчик температури не вказано, інтеграція автоматично
перемикається на пряме порівняння відсотків: дельта — у відсоткових
пунктах (вологість сусідньої кімнати + дельта), без урахування різниці
температур.

Перемикання режиму повністю автоматичне й стосується як самого
розрахунку, так і одиниці виміру `number`-сутності дельти (`%` або
`г/м³`) — нічого вручну переключати не потрібно, досить лише
вказати/прибрати обидва датчики температури в налаштуваннях пристрою.

## Додавання картки

**Важливо: спочатку створи пристрій (крок вище), і лише потім додавай
картку** — без готового пристрою картці нема що показувати.

Картка реєструється автоматично — ресурс Lovelace вручну додавати не
потрібно (якщо все ж не з'явилась — див. розділ нижче). У режимі YAML
достатньо вказати тип:

```yaml
type: custom:ha-smart-dehumidifier
```

Після цього відкрий картку через **візуальний редактор** (вкладка
"Сутності" 🔗) і обери там **Пристрій (HA Smart Dehumidifier)** —
головну сутність (`humidifier`) щойно створеного пристрою. Усе інше —
вимикач вентилятора, датчики, статус, авто-режим, number-сутності тощо
— картка знаходить сама, підмінювати їх вручну не потрібно.

Для YAML-режиму те саме можна вказати одразу, без відкриття редактора:

```yaml
type: custom:ha-smart-dehumidifier
entity: humidifier.smart_xxx
```

Усі візуальні налаштування (розкладка, дуга, кольори, ефекти, шрифт
7-segment тощо) редагуються там само, у візуальному редакторі.

## Як працює авто-режим

Вентилятор вмикається й вимикається за асиметричним гістерезисом
навколо цільової вологості (яку в авто-режимі інтеграція сама рахує —
див. "Навіщо два датчики температури", а в ручному — задає користувач):

- **Вмикається**, щойно поточна вологість дорівнює цільовій або
  перевищує її (`поточна >= ціль`) — без затримки, реагує одразу.
- **Вимикається**, лише коли поточна вологість опуститься нижче
  цільової на величину **гістерезису** (`поточна <= ціль − гістерезис`,
  за замовчуванням 5%).

Це працює однаково незалежно від того, чому саме різниця "поточна −
ціль" змінилась: впала вологість чи просто підняли ціль. Наприклад,
при гістерезисі 5% і цілі 65%: вентилятор вмикається, як тільки
вологість сягає 65%, і вимикається, коли вона опуститься до 60% —
або одразу, якщо підняти ціль до 65%+, поки вологість лишається на
рівні 60% чи нижче. Такий запас потрібен лише на вимкнення — щоб реле
не клацало щоразу, як вологість на мить торкнеться цілі.

Кілька важливих нюансів поведінки:

- **Ручна зміна цільової вологості** (повзунок, кнопки +/-, клік по
  панелі) одразу вимикає авто-режим — щоб наступна ж синхронізація з
  датчиків не перезаписала вибір користувача.
- **Кнопка "Ручний"** завжди інвертує фактичний стан вентилятора: якщо
  зараз крутиться — ставить на паузу; якщо стоїть — вмикає ручним
  таймером (тривалість налаштовується, за замовчуванням 20 хв).
- Після завершення ручного режиму (сплив таймер або вимкнули вручну)
  починається **пауза** (за замовчуванням 20 хв), протягом якої
  авто-режим тимчасово не керує вентилятором — це навмисно, щоб
  ручне втручання не перебивалось одразу ж автоматикою.
- Фізичний вимикач вентилятора теж враховується: якщо його ввімкнули
  "руками" (не через авто-режим) — це стартує ручний режим; вимкнули
  під час ручного — ставить на паузу.

Видимий статус пристрою (сутність `sensor..._status`) відображає, яка
саме з цих причин зараз керує вентилятором:

| Статус | Значення |
|---|---|
| `off` | Пристрій вимкнено. |
| `connecting` | Увімкнено, але датчик поточної вологості ще недоступний (типово — перші секунди після рестарту HA). |
| `auto` | Вентилятор фактично працює через спрацювання вологості. |
| `idle` | Увімкнено, вентилятор не працює — вологість ще не досягла цілі. |
| `manual` | Ручний режим, вологість ще не спрацювала. |
| `manual_auto` | Ручний режим і вологість вже спрацювала одночасно. |
| `pause` | Ручний режим щойно вимкнено — коротка пауза перед поверненням авто-визначення. |

## Налаштування розрахунку

Значення нижче можна змінювати двома способами: живо через шестерню на
самій картці — зберігаються між перезапусками; або одноразово як
стартові — Settings → HA Smart Dehumidifier → Configure.

| Параметр | Значення за замовчуванням |
|---|---|
| Дельта вологості понад сусідню кімнату | 3.75% (робочий діапазон 3.5–4) |
| Мін. рекомендована вологість | 65% |
| Макс. рекомендована вологість | 85% |
| Гістерезис (толерантність, лише в Options) | 5% |
| Тривалість ручного режиму | 20 хв |
| Пауза після ручного режиму | 20 хв |

## Якщо картка не з'являється (Custom element doesn't exist)

1. Перевір, що інтеграція реально завантажилась: Settings → System → Logs →
   пошук "ha_smart_dehumidifier". Якщо бачиш помилку реєстрації ресурсу —
   там же буде вказано, що зробити.
2. Відкрий картку в браузері (F12 → Network), онови сторінку і перевір
   запит `/ha_smart_dehumidifier_files/index.js` — має бути **200**, а не
   404. Якщо 404 — інтеграція не завантажилась (перевір логи) або HA
   потрібно повністю перезапустити (не reload, а restart) після
   встановлення через HACS.
3. Жорстко онови кеш браузера (Ctrl+Shift+R / Cmd+Shift+R).
4. Якщо нічого з вищого не допомогло — додай ресурс вручну: Settings →
   Dashboards → ⋮ → Resources → Add resource → URL
   `/ha_smart_dehumidifier_files/index.js`, тип **JavaScript Module**.
